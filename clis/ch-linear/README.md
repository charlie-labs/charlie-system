# Linear CLI (`ch-linear`)

A developer‑friendly CLI to manage your **Linear** workspace. Quickly create, edit, search, and view issues; list users, labels, workflow states, teams, and projects – all from the terminal.

The repository exposes the CLI through the root `bin/` directory:

```bash
bun run --cwd clis/ch-linear start --help
```

## Configuration

### Environment variables

| Name                  | Required | Description                                                              |
| --------------------- | -------- | ------------------------------------------------------------------------ |
| `LINEAR_ACCESS_TOKEN` | No       | OAuth access token (preferred). Sent as `Authorization: Bearer <token>`. |
| `LINEAR_API_KEY`      | No       | Personal API key. Sent as `Authorization: <key>` (no Bearer prefix).     |

Provide either `LINEAR_ACCESS_TOKEN` or `LINEAR_API_KEY`. When both are set, `LINEAR_ACCESS_TOKEN` takes precedence.

Only environment variables that the CLI actually reads are documented here. If you need to point at a different GraphQL endpoint, pass an `endpoint` when creating the client programmatically; the CLI does not currently read a `LINEAR_API_ENDPOINT` variable.

### Global flags

These flags are available on every command:

- `--json` – Output raw JSON instead of human-oriented tables/TSV.
- `--help` – Show usage information for any command.
- `--version` – Print the installed CLI version.

## Agents mode (sessions + activities)

Agents mode is a set of commands for recording agent runs in Linear.

- **Agent session**: a container tied to an issue or comment (or a generic session via `--app-user-id`) that represents an agent run context.
- **Agent activity**: an event/message within a session (thought/action/response/error/elicitation/prompt).

Many “content” flags support `@file` inputs:

- `@path/to/file` reads the file content.
- `@@...` forces a literal/inline value (disables `@file` parsing):
  - text flags: `@@hello` → `@hello`
  - JSON flags: `@@{"k":"v"}` → `{"k":"v"}`

For the complete command/flag reference, run:

```bash
ch-linear agent-session --help
ch-linear agent-activity --help
```

## Programmatic usage

You can also use this package directly from TypeScript/JavaScript without the CLI. The library is exported from a single namespace at the package root.

```ts
import {
  createLinearClient,
  listIssues,
  type LinearClient,
} from '@charlie-labs/ch-linear';

// Prefer an OAuth access token (Bearer). Fall back to a personal API key.
const client: LinearClient = createLinearClient({
  accessToken: process.env.LINEAR_ACCESS_TOKEN,
  apiKey: process.env.LINEAR_API_KEY,
});

// Run an operation (example: list the 10 most recent issues)
const issues = await listIssues(
  { first: 10, orderBy: 'updatedAt' },
  { client }
);
for (const issue of issues) {
  console.log(`${issue.identifier} - ${issue.title}`);
}
```

Notes:

- The public API intentionally excludes raw GraphQL artifacts and documents used to generate the client.
- All operations and helpers are available from the root import; there are no subpath exports.

## Develop

To begin development, ensure you have Bun setup on your system and the dependencies installed.

```bash
# Start the CLI
bun run --cwd clis/ch-linear start <args forwarded to ch-linear>

# Type‑check, test, and verify migration-owned artifacts
bun run --cwd clis/ch-linear typecheck
bun run --cwd clis/ch-linear test
bun run --cwd clis/ch-linear codegen:verify
bun run --cwd clis/ch-linear examples:verify
```

- No build step required – Bun runs TypeScript directly.
- **MSW pin:** Integration tests rely on `msw@2.3.1` due to a Bun compatibility issue (see issue [oven-sh/bun#13072](https://github.com/oven-sh/bun/issues/13072)).

### GraphQL Code Generation

The project ships with a fully‑typed SDK for the Linear GraphQL API generated by [GraphQL Code Generator](https://www.graphql-code-generator.com/).

- **Sources:** `src/lib/linear/queries/**/*.graphql`
- **Output:** `src/generated/linear-sdk.ts` (types, documents & SDK)

Regenerate whenever you add/change queries or when Linear’s schema updates:

```bash
bun run codegen       # wraps: graphql-codegen --config codegen.yml
```

Files in `src/generated/` are _tracked in Git_ – commit the diff so reviewers can see schema changes.
If you hit merge conflicts, simply delete the file and rerun codegen.

### Command Examples (CI‑enforced)

Every concrete command class (any `src/cli/commands/**/*.ts` file that is **not** a pure re‑export wrapper like `export { default } from './edit.js';`) **must** declare a non‑empty static examples array:

```ts
export default class ProjectList extends Command {
  static description = 'List projects';
  static flags = {
    /* ... */
  };
  static examples = [
    '<%= config.bin %> <%= command.id %>',
    '<%= config.bin %> <%= command.id %> --team CORE --status-type active',
  ];
  // ...
}
```

Tokens inside the strings are templated by oclif at runtime:

- `<%= config.bin %>` – resolves to the installed executable (`ch-linear`)
- `<%= command.id %>` – resolves to the full command id (e.g. `project list`)

You can also write fully expanded examples (e.g. `$ ch-linear issue create --team ENG --title "Bug"`). Keep examples concise, copy‑pastable, and cover at least one common path plus one flag / JSON output scenario.

The repository runs `scripts/verify-examples.ts` to fail the build if any command file is missing `static examples`. Add examples for new commands in the initial commit to keep the history clean.

For authentication and global flags shared across commands, see [Configuration](#configuration).
